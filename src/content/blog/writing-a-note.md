这是一份随网站一起保留的简短说明，方便以后给这个笔记本添上新的一页。

文章不需要在后台编辑。它们就是保存在项目里的 Markdown 文件，可以用熟悉的文本编辑器打开，也可以直接在 GitHub 上修改。

## 新建一篇文章

在项目的 `src/content/blog/` 目录中创建文件，例如 `my-first-note.md`。文件名会成为网址的一部分，因此最好使用简短的英文字母、数字与连字符，发布后不要随意改名。

每个文件开头都有一小段资料：

```yaml
---
title: '我的新文章'
description: '用一两句话介绍这篇文章。'
pubDate: 2026-10-16
tags: ['笔记']
draft: false
---
```

把日期替换为实际发布日期，然后就可以在下方开始写正文。

## 只管写下内容

Markdown 可以直接表达常见的排版，不需要为每一段内容写 HTML。

```markdown
## 一个小标题

这是一段正文，可以有 **重点**，也可以有 *一点强调*。

- 一个想法
- 另一个想法

> 把值得记下的话留在这里。
```

文章标题会由网站自动显示，正文从二级标题 `##` 开始就好。

## 暂时不想公开？

把资料中的 `draft` 改为 `true`。草稿不会生成公开文章页面，也不会出现在首页、文章列表和 RSS 中。

**注意：草稿隐藏不等于文件保密。** GitHub Pages 的公开源码仓库仍然可以被访问。如果内容涉及隐私，请留在本地，不要提交到公开仓库。

## 预览与发布

在本地项目目录运行：

```bash
npm install
npm run dev
```

浏览器打开终端显示的本地地址，就能查看修改。发布前可以再检查一次：

```bash
npm run verify
```

当 GitHub Pages 部署配置完成后，将修改提交到仓库的 `main` 分支，GitHub Actions 就会重新构建网站。等部署成功，新的文章就会出现在站点上。

## 让这份说明退到幕后

这篇文章只是初始的使用指南。如果不想让它出现在文章列表中，可以把它设为草稿，或者删除这个文件。更完整的维护说明也放在项目的 `README.md` 中。
